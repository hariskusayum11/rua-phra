# การนำเว็บไซต์ขึ้นเซิร์ฟเวอร์

เอกสารนี้พาตั้งแต่เลือกโฮสต์จนเว็บเปิดใช้งานได้จริง พร้อมรายการตรวจก่อนวันจัดนิทรรศการ

> **เว็บฝากแบบธรรมดาใช้ไม่ได้** โฮสต์ที่ใช้ลง WordPress (cPanel, DirectAdmin) รันได้แต่ PHP
> เว็บนี้ต้องการ **Node.js รันตลอดเวลา** และ **PostgreSQL** จึงต้องใช้โฮสต์ที่รัน Node ได้

---

## 1. เลือกโฮสต์

| ทาง | ราคาโดยประมาณ | อัปโหลดภาพ | ข้อควรรู้ |
| --- | --- | --- | --- |
| **VPS + Docker** | 200–350 บาท/เดือน | ใช้ได้เลย | ควบคุมได้ทั้งหมด ใช้ไฟล์ในโฟลเดอร์นี้ได้ทันที |
| **Railway** | ~170 บาท/เดือน | ใช้ได้เลย | ตั้งง่ายที่สุด มีฐานข้อมูลในตัว |
| **Vercel + Neon** | ฟรี | **ใช้ไม่ได้** | ต้องแก้โค้ดให้เก็บไฟล์ที่ object storage ก่อน |

**แนะนำ VPS หรือ Railway** เพราะทุกอย่างทำงานเหมือนที่ทดสอบไว้ ไม่ต้องแก้โค้ด

### ทำไม Vercel ถึงมีปัญหา

ระบบเก็บภาพที่อัปโหลดไว้ในโฟลเดอร์ `storage/uploads/` บนเครื่องเซิร์ฟเวอร์
Vercel ไม่มีพื้นที่เก็บไฟล์ถาวร ภาพที่อัปโหลดจะ**ดูเหมือนสำเร็จแล้วหายไปเงียบ ๆ**
เหลือแต่ระเบียนในฐานข้อมูลที่ชี้ไปหาไฟล์ที่ไม่มีอยู่ ซึ่งผู้ดูแลจะไม่รู้ตัวจนสาย

## 2. เตรียมก่อน

### โดเมน

**ตัดสินใจเรื่องโดเมนให้จบก่อนสั่งพิมพ์ป้าย QR** ป้ายที่ติดบนบอร์ดแล้วแก้ไม่ได้
ปลายทางของป้ายเปลี่ยนทีหลังได้ แต่**ชื่อโดเมนเปลี่ยนไม่ได้** เพราะมันถูกพิมพ์ลงไปในรูป QR แล้ว

- ซื้อโดเมน `.com` หรือ `.org` ประมาณ 400 บาท/ปี
- ชี้ A record ของโดเมนมาที่ IP ของเซิร์ฟเวอร์
- รอ DNS กระจายตัวสักครึ่งชั่วโมงก่อนทำขั้นต่อไป

### ค่าที่ต้องเตรียม

สร้างรหัสลับด้วยคำสั่งนี้ (ใช้คนละค่าสำหรับแต่ละตัว)

```bash
openssl rand -base64 48
```

| ตัวแปร | ใส่อะไร |
| --- | --- |
| `SITE_DOMAIN` | โดเมนจริง เช่น `ruaphra.org` ไม่ต้องใส่ `https://` |
| `POSTGRES_PASSWORD` | รหัสผ่านฐานข้อมูล ตั้งใหม่ ห้ามใช้ค่าเดียวกับตอนพัฒนา |
| `AUTH_SECRET` | ค่าสุ่มยาวจากคำสั่งด้านบน |
| `ADMIN_EMAIL` | อีเมลที่ใช้เข้าระบบผู้ดูแล |
| `ADMIN_PASSWORD` | รหัสผ่านผู้ดูแล ตั้งให้แข็งแรง |

## 3. วิธี A — VPS ด้วย Docker

ใช้ได้กับ DigitalOcean, Vultr, Linode หรือผู้ให้บริการไทยอย่าง Netway, Ruk-com
เลือกเครื่องขนาดเล็กสุดที่มี **RAM 2 GB ขึ้นไป** และติดตั้ง Ubuntu

### 3.1 ติดตั้ง Docker บนเซิร์ฟเวอร์

```bash
curl -fsSL https://get.docker.com | sh
```

### 3.2 นำโค้ดขึ้นเซิร์ฟเวอร์

```bash
git clone https://github.com/hariskusayum11/rua-phra.git
cd rua-phra
```

### 3.3 ตั้งค่า

```bash
cp .env.example .env
nano .env
```

ลบเครื่องหมาย `#` หน้าส่วน production แล้วกรอกค่าจริงทั้งหมดตามตารางข้อ 2

### 3.4 เปิดใช้งาน

```bash
docker compose -f compose.prod.yaml up -d --build
```

คำสั่งเดียวนี้จะ build เว็บ เปิดฐานข้อมูล ปรับโครงสร้างฐานข้อมูลให้เป็นปัจจุบัน
และขอใบรับรอง HTTPS ให้อัตโนมัติ รอบแรกใช้เวลาประมาณ 5–10 นาที

ดูว่าขึ้นครบหรือยัง

```bash
docker compose -f compose.prod.yaml ps
```

ดูบันทึกการทำงานเมื่อมีปัญหา

```bash
docker compose -f compose.prod.yaml logs -f web
```

### 3.5 อัปเดตเว็บเมื่อแก้โค้ด

```bash
git pull && docker compose -f compose.prod.yaml up -d --build
```

## 4. วิธี B — Railway

1. สมัครที่ railway.app แล้วสร้าง project ใหม่
2. เลือก **Deploy from GitHub repo** แล้วเลือกรีโพนี้
3. กด **New → Database → PostgreSQL** ในโปรเจกต์เดียวกัน
4. ที่บริการเว็บ เปิดแท็บ **Variables** แล้วใส่

   | ตัวแปร | ค่า |
   | --- | --- |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `NEXT_PUBLIC_SITE_URL` | ที่อยู่เว็บที่ Railway ให้มา หรือโดเมนจริง |
   | `AUTH_URL` | เหมือน `NEXT_PUBLIC_SITE_URL` |
   | `AUTH_SECRET` | ค่าสุ่มยาว |
   | `ADMIN_EMAIL` / `ADMIN_PASSWORD` | ค่าที่ตั้งไว้ |

5. เปิดแท็บ **Settings → Volumes** เพิ่ม volume ชี้ไปที่ `/app/storage/uploads`
   **ข้ามขั้นนี้ไม่ได้** ไม่งั้นภาพที่อัปโหลดจะหายทุกครั้งที่ deploy ใหม่

## 5. ย้ายข้อมูลจากเครื่องตัวเองขึ้นเซิร์ฟเวอร์

ฐานข้อมูลบนเซิร์ฟเวอร์จะว่างเปล่าตอนเริ่ม ต้องย้ายข้อมูลภาคสนามขึ้นไป

**สำรองจากเครื่องตัวเอง** (เปิด Docker Desktop ไว้ก่อน)

```bash
docker exec rua_phra_story-db-1 pg_dump -U rua -d rua_phra --data-only --disable-triggers > backup.sql
```

**นำขึ้นเซิร์ฟเวอร์**

```bash
scp backup.sql user@เซิร์ฟเวอร์:/tmp/
```

**นำเข้าบนเซิร์ฟเวอร์**

```bash
docker compose -f compose.prod.yaml exec -T db psql -U rua -d rua_phra < /tmp/backup.sql
```

**ภาพที่อัปโหลดผ่านหน้าแอดมิน** อยู่ในโฟลเดอร์ `storage/uploads/` ของเครื่องตัวเอง
ต้องคัดลอกขึ้นไปด้วย ส่วนภาพและวิดีโอใน `public/` ติดไปกับโค้ดอยู่แล้ว

## 6. รายการตรวจก่อนเปิดจริง

- [ ] กรอกค่าใน `.env` ครบ และ**ไม่มีค่าตัวอย่างหลงเหลือ**
- [ ] เปิด `https://โดเมนจริง` แล้วขึ้นหน้าแรกได้ มีกุญแจล็อกในแถบที่อยู่
- [ ] เข้า `/admin` ได้ด้วยรหัสผ่านใหม่ และ**เข้าด้วยรหัสเดิมไม่ได้**
- [ ] ลองอัปโหลดภาพหนึ่งใบ แล้ว `docker compose -f compose.prod.yaml restart web` แล้วเช็กว่าภาพยังอยู่
- [ ] ตั้ง `NEXT_PUBLIC_SITE_URL` เป็นโดเมนจริง แล้วเปิด `/admin/qr-print` **ต้องไม่มีคำเตือนสีส้ม**
- [ ] สแกน QR ด้วยโทรศัพท์จริงจากอินเทอร์เน็ตมือถือ ไม่ใช่ wifi บ้าน
- [ ] ลบ `robots: { index: false, follow: false }` ออกจาก `src/app/layout.tsx` เมื่อพร้อมให้เสิร์ชเอนจินเก็บข้อมูล
- [ ] ตั้งการสำรองฐานข้อมูลอัตโนมัติ หรืออย่างน้อยสั่ง `pg_dump` เก็บไว้ก่อนวันงาน

## 7. แผนสำรองวันจัดงาน

สัญญาณอินเทอร์เน็ตในห้องจัดนิทรรศการเป็นสิ่งที่ควบคุมไม่ได้ และ QR ที่สแกนไม่ขึ้นต่อหน้ากรรมการ
แก้ตรงนั้นไม่ทัน เตรียมสามอย่างนี้ไว้

1. **แท็บเล็ตหรือโน้ตบุ๊กที่บูธ** เปิดเว็บค้างไว้แล้ว ให้คนดูได้ทันทีโดยไม่ต้องสแกน
2. **สำเนาที่รันบนเครื่องตัวเอง** ถ้าอินเทอร์เน็ตล่ม ยังเปิด `npm run dev` บนโน้ตบุ๊กแล้วปล่อยฮอตสปอตให้สแกนได้
   แต่ต้องเตรียม QR อีกชุดที่ชี้ไปที่อยู่ของเครื่องนั้น เพราะ QR บนบอร์ดชี้ไปโดเมนจริง
3. **ภาพหน้าจอสำคัญพิมพ์ใส่แฟ้ม** กันกรณีที่แย่ที่สุด

**ตรวจเว็บอีกครั้งในเช้าวันงาน** เปิดหน้าแรก สแกน QR หนึ่งดวง และดูว่าหน้า `/exhibition` ขึ้นครบ
