# การนำเว็บไซต์ขึ้นเซิร์ฟเวอร์

เอกสารนี้พาตั้งแต่เลือกโฮสต์จนเว็บเปิดใช้งานได้จริง พร้อมรายการตรวจก่อนวันจัดนิทรรศการ

> **เว็บฝากแบบธรรมดาใช้ไม่ได้** โฮสต์ที่ใช้ลง WordPress (cPanel, DirectAdmin) รันได้แต่ PHP
> เว็บนี้ต้องการ **Node.js รันตลอดเวลา** และ **PostgreSQL** จึงต้องใช้โฮสต์ที่รัน Node ได้

---

## 1. เลือกโฮสต์

| ทาง | ราคาโดยประมาณ | อัปโหลดภาพ | ข้อควรรู้ |
| --- | --- | --- | --- |
| **VPS + Docker** | 200–350 บาท/เดือน | ใช้ได้เลย | ควบคุมได้ทั้งหมด ใช้ไฟล์ในโฟลเดอร์นี้ได้ทันที |
| **Railway** | ~170 บาท/เดือน | ใช้ได้เลย | ตั้งง่ายที่สุด มีฐานข้อมูลในตัว |
| **Vercel + Neon + R2** | ฟรี | ใช้ได้ | ผูกกับบริการภายนอกสามเจ้า ดูขั้นตอนข้อ 3 |

**ถ้างบจำกัด แนะนำทางฟรีในข้อ 3** ถ้าอยากให้ทุกอย่างอยู่ในเครื่องเดียวที่ควบคุมเองได้ ใช้ VPS ในข้อ 4

### เรื่องที่เก็บไฟล์

ระบบเก็บภาพที่อัปโหลดไว้ในโฟลเดอร์ `storage/uploads/` ของเครื่องเซิร์ฟเวอร์
**Vercel ไม่มีพื้นที่เก็บไฟล์ถาวร** ภาพที่อัปโหลดจะหายไปเงียบ ๆ เหลือแต่ระเบียนที่ชี้ไปหาไฟล์ที่ไม่มีอยู่

ระบบจึงรองรับที่เก็บไฟล์ภายนอกด้วย ถ้าตั้งค่า **Cloudflare R2** ครบทั้ง 5 ค่า ภาพที่อัปโหลดจะไปอยู่ที่นั่นแทน
ถ้าไม่ตั้งค่าเลย จะเขียนลงดิสก์เหมือนเดิม **ต้องครบทั้งหมดหรือไม่ใส่เลย** เพื่อไม่ให้ตั้งค่าไว้ครึ่ง ๆ กลาง ๆ

## 2. เตรียมก่อน

### โดเมน

**ตัดสินใจเรื่องโดเมนให้จบก่อนสั่งพิมพ์ป้าย QR** ป้ายที่ติดบนบอร์ดแล้วแก้ไม่ได้
ปลายทางของป้ายเปลี่ยนทีหลังได้ แต่**ชื่อโดเมนเปลี่ยนไม่ได้** เพราะมันถูกพิมพ์ลงไปในรูป QR แล้ว

- ซื้อโดเมน `.com` หรือ `.org` ประมาณ 400 บาท/ปี
- ชี้ A record ของโดเมนมาที่ IP ของเซิร์ฟเวอร์
- รอ DNS กระจายตัวสักครึ่งชั่วโมงก่อนทำขั้นต่อไป

### ค่าที่ต้องเตรียม

สร้างรหัสลับด้วยคำสั่งนี้ (ใช้คนละค่าสำหรับแต่ละตัว)

```bash
openssl rand -base64 48
```

| ตัวแปร | ใส่อะไร |
| --- | --- |
| `SITE_DOMAIN` | โดเมนจริง เช่น `ruaphra.org` ไม่ต้องใส่ `https://` |
| `POSTGRES_PASSWORD` | รหัสผ่านฐานข้อมูล ตั้งใหม่ ห้ามใช้ค่าเดียวกับตอนพัฒนา |
| `AUTH_SECRET` | ค่าสุ่มยาวจากคำสั่งด้านบน |
| `ADMIN_EMAIL` | อีเมลที่ใช้เข้าระบบผู้ดูแล |
| `ADMIN_PASSWORD` | รหัสผ่านผู้ดูแล ตั้งให้แข็งแรง |

## 3. วิธีฟรี — Vercel + Neon + Cloudflare R2

ไม่มีค่าใช้จ่ายรายเดือน ใช้สามบริการที่มีแพ็กฟรีถาวร สมัครด้วยบัญชี GitHub ทั้งหมด ไม่ต้องใช้บัตรเครดิต

| บริการ | ทำหน้าที่ | แพ็กฟรีให้อะไร |
| --- | --- | --- |
| **Vercel** | รันเว็บไซต์ | 100 GB ปริมาณข้อมูลต่อเดือน |
| **Neon** | ฐานข้อมูล PostgreSQL | พื้นที่ 0.5 GB |
| **Cloudflare R2** | เก็บภาพและวิดีโอ | พื้นที่ 10 GB และไม่คิดค่าส่งข้อมูลออก |

> แพ็กฟรีของ Vercel ใช้กับงานที่ไม่แสวงหากำไรเท่านั้น โครงการวิจัยและการศึกษาเข้าเงื่อนไข

### 3.1 สร้างฐานข้อมูลที่ Neon

1. สมัครที่ neon.tech ด้วยบัญชี GitHub แล้วสร้าง project ใหม่ เลือก region **Singapore** เพราะใกล้ไทยที่สุด
2. คัดลอกค่า **Connection string** เก็บไว้ จะใช้เป็น `DATABASE_URL`

### 3.2 สร้างที่เก็บไฟล์ที่ Cloudflare R2

1. สมัครที่ cloudflare.com แล้วเข้าเมนู **R2 Object Storage** กด **Create bucket**
   ตั้งชื่อ `ruaphra-media` เลือก Location **Asia-Pacific (APAC)** เพราะใกล้ไทยที่สุด

2. เข้าแท็บ **Settings** ของ bucket หาหัวข้อ **Public Development URL**
   (เมนูนี้เคยชื่อ Public access — Cloudflare เปลี่ยนชื่อแล้ว) กด **Enable** ทางขวา
   จะได้ที่อยู่หน้าตาแบบ `https://pub-xxxxxxxx.r2.dev` เก็บไว้เป็น `NEXT_PUBLIC_MEDIA_BASE_URL`

   > **ที่อยู่นี้ Cloudflare จำกัดอัตราการเรียกและระบุว่าไม่เหมาะกับการใช้งานจริง**
   > ใช้สำหรับทดสอบไปก่อนได้ แต่ก่อนวันจัดนิทรรศการควรเปลี่ยนไปใช้ Custom Domain ตามข้อ 3.2.2
   > ซึ่งไม่มีข้อจำกัดนี้และไม่มีค่าใช้จ่ายเพิ่ม

3. **Account ID** คัดลอกได้จากหัวข้อ **General** ในหน้าเดียวกัน บรรทัด **S3 API**
   เป็นส่วนที่อยู่หลัง `https://` และก่อน `.r2.cloudflarestorage.com` เก็บไว้เป็น `R2_ACCOUNT_ID`

4. กลับไปหน้า R2 หลัก กด **Manage API Tokens → Create API Token**
   เลือกสิทธิ์ **Object Read & Write** เฉพาะ bucket นี้
   จะได้ **Access Key ID** และ **Secret Access Key**

   > **Secret Access Key แสดงครั้งเดียว** คัดลอกใส่ `.env` ทันที และอย่าส่งต่อทางแชต
   > อย่าแคปหน้าจอที่มีค่านี้ และอย่า commit ขึ้น git

### 3.2.2 เปลี่ยนไปใช้ Custom Domain ก่อนวันงาน

ที่อยู่ `r2.dev` ถูกจำกัดอัตราการเรียก ถ้ามีคนสแกน QR พร้อมกันหลายคนที่บูธ ภาพอาจโหลดไม่ขึ้น
แก้ด้วยการผูกโดเมนย่อยของตัวเอง ฟรีและไม่มีลิมิต

1. ย้าย DNS ของโดเมนมาที่ Cloudflare (ทำตอนซื้อโดเมนหรือย้ายทีหลังก็ได้)
2. ที่หน้า bucket → **Settings** → **Custom Domains** → **Add**
   ใส่โดเมนย่อย เช่น `media.ruaphra.org` Cloudflare จะสร้าง DNS record ให้เอง
3. เปลี่ยน `NEXT_PUBLIC_MEDIA_BASE_URL` เป็น `https://media.ruaphra.org` แล้ว deploy ใหม่
4. **ที่อยู่ของไฟล์เดิมจะเปลี่ยนตาม** ต้องแก้ค่าในฐานข้อมูลด้วย รันสคริปต์ย้ายสื่ออีกครั้ง
   หรือบอกผมให้เขียนคำสั่งแก้ที่อยู่ให้

### 3.2.1 เปิด CORS ให้เบราว์เซอร์อัปโหลดวิดีโอได้

วิดีโอส่งจากเบราว์เซอร์ไปยัง R2 โดยตรง ไม่ผ่านเซิร์ฟเวอร์ เพราะไฟล์ใหญ่เกินกว่าที่เซิร์ฟเวอร์รับได้
จึงต้องอนุญาตให้เว็บไซต์เขียนลง bucket ได้ **ถ้าไม่ตั้งค่านี้ การอัปโหลดวิดีโอจะล้มโดยไม่บอกสาเหตุ**

ที่หน้า bucket → **Settings** → เมนูซ้ายมือ **CORS Policy** → **Add CORS policy** ใส่ตามนี้
แล้วเปลี่ยน `AllowedOrigins` เป็นที่อยู่จริงของเว็บไซต์

```json
[
  {
    "AllowedOrigins": ["https://ที่อยู่เว็บไซต์ของคุณ"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type"],
    "MaxAgeSeconds": 3600
  }
]
```

ถ้าจะทดสอบจากเครื่องตัวเองด้วย ให้ใส่ `"http://localhost:3000"` เพิ่มเข้าไปในรายการ

### 3.3 ย้ายวิดีโอขึ้น R2

ทำจากเครื่องตัวเอง ก่อน deploy ใส่ค่า R2 ทั้ง 5 ลงใน `.env` แล้วลองดูก่อนว่าจะย้ายอะไรบ้าง

```powershell
npx tsx scripts/migrate-media-to-r2.mjs --dry-run
```

พอใจแล้วย้ายจริง

```powershell
npx tsx scripts/migrate-media-to-r2.mjs
```

สคริปต์จะอัปโหลดวิดีโอและภาพปกขึ้น R2 แล้วแก้ที่อยู่ในฐานข้อมูลให้ **ไม่ลบไฟล์ต้นฉบับ**
เปิดเว็บดูให้แน่ใจว่าวิดีโอยังเล่นได้ แล้วค่อยเอาไฟล์ออกจากรีโพ

```powershell
git rm -r --cached public/videos
"public/videos" | Out-File -Append -Encoding utf8 .gitignore
git commit -m "ย้ายวิดีโอไปเก็บที่ R2"
```

### 3.4 นำเว็บขึ้น Vercel

1. สมัครที่ vercel.com ด้วยบัญชี GitHub กด **Add New → Project** แล้วเลือกรีโพนี้
2. ก่อนกด Deploy เปิดหัวข้อ **Environment Variables** ใส่ให้ครบ

   | ตัวแปร | ค่า |
   | --- | --- |
   | `DATABASE_URL` | connection string จาก Neon |
   | `NEXT_PUBLIC_SITE_URL` | ที่อยู่เว็บ ใส่ทีหลังได้เมื่อรู้ชื่อแล้ว |
   | `AUTH_SECRET` | ค่าสุ่มยาว |
   | `ADMIN_EMAIL` / `ADMIN_PASSWORD` | ค่าที่ตั้งไว้ |
   | `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` | ค่าจากข้อ 3.2 |
   | `NEXT_PUBLIC_MEDIA_BASE_URL` | ที่อยู่ public ของ bucket |

3. กด **Deploy** รอประมาณ 3–5 นาที
4. ปรับโครงสร้างฐานข้อมูลบน Neon โดยรันจากเครื่องตัวเอง ชี้ `DATABASE_URL` ไปที่ Neon

   ```powershell
   npx prisma migrate deploy
   ```

5. ย้ายข้อมูลขึ้นไปตามข้อ 6
6. กลับมาแก้ `NEXT_PUBLIC_SITE_URL` ให้เป็นที่อยู่จริง แล้วกด **Redeploy**

### 3.5 กันไม่ให้เกินโควตาฟรีแล้วถูกเรียกเก็บเงิน

R2 คิดเงินเมื่อใช้เกินโควตา ไม่ได้หยุดให้เอง ระบบจึงมีตัวกันไว้สามชั้น

**ชั้นที่ 1 — เพดานในระบบต่ำกว่าโควตาฟรี**
ตั้งไว้ที่ 8 GB ขณะที่ Cloudflare ให้ฟรี 10 GB ช่องว่าง 2 GB คือกันชน
ปรับได้ที่ตัวแปร `R2_MAX_BYTES` แต่**ตั้งเกิน 10 GB ไม่ได้** ระบบจะไม่รับค่าที่สูงกว่าเส้นที่เริ่มคิดเงิน

**ชั้นที่ 2 — ถึงเพดานแล้วหยุดรับไฟล์**
การอัปโหลดจะถูกปฏิเสธพร้อมบอกว่าใช้ไปเท่าไรและต้องทำอย่างไร
ถ้าติดต่อ R2 ไม่ได้ ระบบก็จะไม่รับไฟล์เช่นกัน เพราะไม่รู้ว่าเหลือพื้นที่เท่าไร

**ชั้นที่ 3 — ดูได้ตลอดเวลาที่ `/admin/storage`**
แสดงปริมาณที่ใช้ เทียบกับทั้งเพดานและโควตาฟรี พร้อมบอกว่าใส่ภาพได้อีกกี่ใบ

**ตั้งการแจ้งเตือนที่ Cloudflare ด้วย** เข้าหน้า Cloudflare → **Notifications** → **Add**
เลือกหมวด **R2** กำหนดเกณฑ์ที่ต้องการ แล้วใส่อีเมล ระบบจะเตือนก่อนถึงโควตา

#### ตัวเลขจริงของโครงการนี้

| รายการ | โควตาฟรีต่อเดือน | ที่ใช้จริง |
| --- | --- | --- |
| พื้นที่เก็บ | 10 GB | **39 MB** (0.38%) |
| การเขียนไฟล์ | 1,000,000 ครั้ง | ไม่กี่สิบครั้ง |
| การอ่านไฟล์ | 10,000,000 ครั้ง | ต่ำมาก และยังถูกแคชไว้อีกชั้น |
| ค่าส่งข้อมูลออก | **ไม่คิดเงิน** | — |

ต้องมีไฟล์มากกว่าปัจจุบัน **260 เท่า** จึงจะเริ่มเสียเงิน และถ้าเกินไป 1 GB
ค่าใช้จ่ายคือประมาณ 0.50 บาทต่อเดือน

### 3.6 ข้อจำกัดที่ควรรู้

- ภาพที่อัปโหลดผ่านแอดมินจะถูก**ย่อขนาดในเบราว์เซอร์ก่อนส่ง** เพราะ Vercel จำกัดขนาดคำขอไว้ไม่กี่เมกะไบต์
  ภาพจากกล้องจริงจึงอัปโหลดได้ตามปกติ และเซิร์ฟเวอร์ยังประมวลผลซ้ำเพื่อลบ EXIF อยู่เหมือนเดิม
- ถ้าเจอข้อความว่าย่อขนาดไม่สำเร็จ ให้บันทึกภาพเป็น JPG หรือ WebP ก่อนแล้วลองใหม่
- ฐานข้อมูลฟรีของ Neon จะพักตัวเมื่อไม่มีคนใช้ คำขอแรกหลังพักจะช้ากว่าปกติประมาณหนึ่งวินาที
- **วิดีโออัปโหลดจากหน้าแอดมินได้** ไม่เกิน 300MB ส่งตรงจากเบราว์เซอร์ไปยัง R2 มีแถบแสดงความคืบหน้า
  ระบบอ่านความยาวและเก็บภาพปกจากวินาทีที่ 3 ให้เอง ต้องเปิด CORS ตามข้อ 3.2.1 ก่อน

## 4. วิธี A — VPS ด้วย Docker

ใช้ได้กับ DigitalOcean, Vultr, Linode หรือผู้ให้บริการไทยอย่าง Netway, Ruk-com
เลือกเครื่องขนาดเล็กสุดที่มี **RAM 2 GB ขึ้นไป** และติดตั้ง Ubuntu

### 4.1 ติดตั้ง Docker บนเซิร์ฟเวอร์

```bash
curl -fsSL https://get.docker.com | sh
```

### 4.2 นำโค้ดขึ้นเซิร์ฟเวอร์

```bash
git clone https://github.com/hariskusayum11/rua-phra.git
cd rua-phra
```

### 4.3 ตั้งค่า

```bash
cp .env.example .env
nano .env
```

ลบเครื่องหมาย `#` หน้าส่วน production แล้วกรอกค่าจริงทั้งหมดตามตารางข้อ 2

### 4.4 เปิดใช้งาน

```bash
docker compose -f compose.prod.yaml up -d --build
```

คำสั่งเดียวนี้จะ build เว็บ เปิดฐานข้อมูล ปรับโครงสร้างฐานข้อมูลให้เป็นปัจจุบัน
และขอใบรับรอง HTTPS ให้อัตโนมัติ รอบแรกใช้เวลาประมาณ 5–10 นาที

ดูว่าขึ้นครบหรือยัง

```bash
docker compose -f compose.prod.yaml ps
```

ดูบันทึกการทำงานเมื่อมีปัญหา

```bash
docker compose -f compose.prod.yaml logs -f web
```

### 4.5 อัปเดตเว็บเมื่อแก้โค้ด

```bash
git pull && docker compose -f compose.prod.yaml up -d --build
```

4. ที่บริการเว็บ เปิดแท็บ **Variables** แล้วใส่

   | ตัวแปร | ค่า |
   | --- | --- |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `NEXT_PUBLIC_SITE_URL` | ที่อยู่เว็บที่ Railway ให้มา หรือโดเมนจริง |
   | `AUTH_URL` | เหมือน `NEXT_PUBLIC_SITE_URL` |
   | `AUTH_SECRET` | ค่าสุ่มยาว |
   | `ADMIN_EMAIL` / `ADMIN_PASSWORD` | ค่าที่ตั้งไว้ |

5. เปิดแท็บ **Settings → Volumes** เพิ่ม volume ชี้ไปที่ `/app/storage/uploads`
   **ข้ามขั้นนี้ไม่ได้** ไม่งั้นภาพที่อัปโหลดจะหายทุกครั้งที่ deploy ใหม่

## 6. ย้ายข้อมูลจากเครื่องตัวเองขึ้นเซิร์ฟเวอร์

ฐานข้อมูลบนเซิร์ฟเวอร์จะว่างเปล่าตอนเริ่ม ต้องย้ายข้อมูลภาคสนามขึ้นไป

### ขึ้น Neon หรือฐานข้อมูลที่ผู้ให้บริการจัดการให้

ใส่ `NEON_DIRECT_URL` (เส้นที่**ไม่มี** `-pooler`) ลง `.env` แล้วสร้างตารางก่อน

```powershell
$env:DATABASE_URL = $env:NEON_DIRECT_URL
npx prisma migrate deploy
```

จากนั้นคัดลอกข้อมูล ดูก่อนได้ว่าจะย้ายอะไรบ้าง

```powershell
npx tsx scripts/push-data-to-server.mjs --dry-run
npx tsx scripts/push-data-to-server.mjs
```

> **ทำไมไม่ใช้ `pg_dump` ตรง ๆ** คำสั่งที่เห็นทั่วไปคือ `pg_dump --data-only --disable-triggers`
> แล้วส่งเข้า `psql` แต่การปิด trigger เป็นสิทธิ์ระดับ superuser ซึ่งผู้ให้บริการแบบจัดการให้
> ไม่มอบให้ การนำเข้าจะหยุดที่ foreign key แรกที่เจอ สคริปต์นี้จึง**เรียงลำดับตารางตาม
> ความสัมพันธ์แทนการปิดการตรวจสอบ** และเติมค่าที่อ้างถึงตารางตัวเองในรอบที่สอง
>
> สคริปต์จะไม่เขียนทับฐานข้อมูลที่มีข้อมูลอยู่แล้ว เว้นแต่เติม `--force`

### ขึ้นเซิร์ฟเวอร์ของตัวเองที่มีสิทธิ์เต็ม

```bash
docker exec rua_phra_story-db-1 pg_dump -U rua -d rua_phra --data-only --disable-triggers > backup.sql
scp backup.sql user@เซิร์ฟเวอร์:/tmp/
docker compose -f compose.prod.yaml exec -T db psql -U rua -d rua_phra < /tmp/backup.sql
```

**ภาพที่อัปโหลดผ่านหน้าแอดมิน** อยู่ในโฟลเดอร์ `storage/uploads/` ของเครื่องตัวเอง
ต้องคัดลอกขึ้นไปด้วย ส่วนภาพและวิดีโอใน `public/` ติดไปกับโค้ดอยู่แล้ว

## 7. รายการตรวจก่อนเปิดจริง

- [ ] กรอกค่าใน `.env` ครบ และ**ไม่มีค่าตัวอย่างหลงเหลือ**
- [ ] เปิด `https://โดเมนจริง` แล้วขึ้นหน้าแรกได้ มีกุญแจล็อกในแถบที่อยู่
- [ ] เข้า `/admin` ได้ด้วยรหัสผ่านใหม่ และ**เข้าด้วยรหัสเดิมไม่ได้**
- [ ] ลองอัปโหลดภาพหนึ่งใบ แล้ว `docker compose -f compose.prod.yaml restart web` แล้วเช็กว่าภาพยังอยู่
- [ ] ตั้ง `NEXT_PUBLIC_SITE_URL` เป็นโดเมนจริง แล้วเปิด `/admin/qr-print` **ต้องไม่มีคำเตือนสีส้ม**
- [ ] สแกน QR ด้วยโทรศัพท์จริงจากอินเทอร์เน็ตมือถือ ไม่ใช่ wifi บ้าน
- [ ] ลบ `robots: { index: false, follow: false }` ออกจาก `src/app/layout.tsx` เมื่อพร้อมให้เสิร์ชเอนจินเก็บข้อมูล
- [ ] ตั้งการสำรองฐานข้อมูลอัตโนมัติ หรืออย่างน้อยสั่ง `pg_dump` เก็บไว้ก่อนวันงาน

## 8. แผนสำรองวันจัดงาน

สัญญาณอินเทอร์เน็ตในห้องจัดนิทรรศการเป็นสิ่งที่ควบคุมไม่ได้ และ QR ที่สแกนไม่ขึ้นต่อหน้ากรรมการ
แก้ตรงนั้นไม่ทัน เตรียมสามอย่างนี้ไว้

1. **แท็บเล็ตหรือโน้ตบุ๊กที่บูธ** เปิดเว็บค้างไว้แล้ว ให้คนดูได้ทันทีโดยไม่ต้องสแกน
2. **สำเนาที่รันบนเครื่องตัวเอง** ถ้าอินเทอร์เน็ตล่ม ยังเปิด `npm run dev` บนโน้ตบุ๊กแล้วปล่อยฮอตสปอตให้สแกนได้
   แต่ต้องเตรียม QR อีกชุดที่ชี้ไปที่อยู่ของเครื่องนั้น เพราะ QR บนบอร์ดชี้ไปโดเมนจริง
3. **ภาพหน้าจอสำคัญพิมพ์ใส่แฟ้ม** กันกรณีที่แย่ที่สุด

**ตรวจเว็บอีกครั้งในเช้าวันงาน** เปิดหน้าแรก สแกน QR หนึ่งดวง และดูว่าหน้า `/exhibition` ขึ้นครบ
