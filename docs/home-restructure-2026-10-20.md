# แก้หน้าแรกและข้อความที่ไม่มีหลักฐาน — 20 ตุลาคม 2569

## รอบเพิ่มภาพและงานตกแต่ง

- เพิ่มภาพให้การ์ด 4 แกนและการ์ดเรียนรู้ ภาพดึงจากบันทึกเรือ ส่วนประกอบ ลวดลาย และขั้นตอนที่ไม่ใช่ข้อมูลสาธิต ไม่มีการ hardcode URL ภาพเนื้อหา
- ภาพประกอบบทเรียนระบุว่าเป็นภาพจากคลังงานช่าง เพราะ Course ยังไม่มีความสัมพันธ์กับภาพปกโดยตรง ไม่ใช้ภาพประกอบเป็นหลักฐานยืนยันว่าบทเรียนสาธิตเป็นเนื้อหาจริง
- เพิ่ม SVG ลายเส้นฉลุประยุกต์ เส้นน้ำ และพื้นผิวกระดาษ ใช้เป็นภาพตกแต่งที่ไม่มีความหมายทางข้อมูล ไม่ระบุว่าเป็นลายท้องถิ่นที่ผ่านการยืนยัน ลายอยู่ตามขอบหน้า ลดความเข้มบนมือถือและไม่รับ pointer events
- ใช้ลายชุดเดียวกันในหน้าแรก หน้าคลัง หน้างานช่าง หน้าเรียนรู้ และหน้าประกวด ปรับกริดคลังให้ขยายตามจำนวนรายการ งานช่างเป็นการ์ดภาพพร้อมข้อความ และหน้าเรียนรู้มีภาพประกอบ
- กรอบภาพเรือใช้ outline ภายนอก จึงไม่เปลี่ยนพื้นที่อ้างอิงของพิกัด hotspot
- ไม่เพิ่ม dependency ใหม่ ใช้ SVG/CSS ร่วมกับ Next Image และระบบ motion ที่มีอยู่ รองรับ reduced motion
- production build ผ่าน; public browser tests 35 ผ่าน รวมการโหลดภาพการ์ดและการเปิดแผงด้วยคีย์บอร์ด

- [ผลตรวจ 29 กรณี](../artifacts/artful-theme/results.json): ไม่พบภาพเสีย หน้าแนวนอนล้น page error หรือ axe violations ในสถานะที่ตรวจ

ตรวจจากโค้ดและหน้าเว็บในเครื่อง รวมถึงอ่านข้อมูล Boat, Pattern, ProcessStep และ Course แบบอ่านอย่างเดียว เอกสารที่แนบเป็นบันทึกการทำงานรอบก่อน ไม่ใช่แหล่งยืนยันข้อเท็จจริงทางวัฒนธรรม

## สิ่งที่พบและแก้ไข

- โครงหน้าแรกค้างอยู่เพียง 5 ช่วง คอมโพเนนต์ 4 แกนไม่มี CSS รองรับ และ stylesheet ยังมีส่วนของหน้าเก่าที่ถูกลบไปแล้ว
- เพิ่มข้อความงานไม้แกะสลักลงในบทนำโดยไม่มีข้อมูลรองรับในงานที่ตรวจ และผูก “ศรัทธา” กับจำนวนปีประกวด จึงเอาข้อความและตัวเลขนั้นออก ใช้คำอธิบายปลายทางที่ตรงกับหน้าที่เปิด
- เนื้อหาวิดีโอเติมข้ออ้างว่าใช้เวลาหลายเดือนและทั้งชุมชนร่วมลากเรือ เปลี่ยนเป็นคำอธิบายการเปิดชมบันทึกที่เชื่อมกับเรือลำนั้น
- หน้าเกี่ยวกับโครงการอ้างว่าทุกภาพได้รับอนุญาตครบและทุกไฟล์ลบตำแหน่งแล้ว แต่ไม่มีหลักฐานการตรวจทุกชิ้นในการตรวจครั้งนี้ เปลี่ยนเป็นข้อมูลตรวจสิทธิ์รายชิ้นและช่องทางแจ้งแก้ไข
- แก้ `VerificationNote` ให้ข้อมูลสาธิตมีป้ายเสมอ แม้สถานะ workflow ถูกตั้ง VERIFIED/PUBLISHED
- ภาพทิวทัศน์ตกแต่งส่วนท้ายไม่มีแหล่งข้อมูลตำแหน่งที่ยืนยันในงานรอบนี้ จึงใช้พื้นครามเรียบต่อกับ CTA เพื่อไม่ให้ภาพตกแต่งถูกเข้าใจเป็นบันทึกสถานที่

## โครงที่แสดงจริง

1. Hero: ภาพเรือจากฐานข้อมูล บนมือถือภาพอยู่เหนือตัวหนังสือ
2. ศิลปะ / ศรัทธา / เรื่องเล่า / ภูมิปัญญา: คำอธิบายสั้น ไม่มีตัวเลขที่นำมาแทนความหมายของแต่ละแกน
3. งานกระดาษ: ภาพหนึ่งภาพและทางเข้าสูงสุด 3 ขั้นตอนจากฐานข้อมูล
4. เรือไฮไลต์: หนึ่งลำ พร้อมลิงก์ดูเรือทั้งหมด รายชื่อส่วนประกอบ และแผงรายละเอียด
5. ลวดลาย: สูงสุด 4 รายการที่ไม่ใช่ข้อมูลสาธิต
6. เรียนรู้: การ์ดเดียว อ่านสถานะสาธิตได้ก่อนคลิก
7. โครงการ: สรุปสั้นและลิงก์ `/about`
8. CTA: ครามเข้ม มีคลื่นเฉพาะขอบบน
9. Footer

บนมือถือ หมายเลขบนภาพเป็นตัวอ้างอิง ใช้ปุ่มรายชื่อด้านล่างที่แยกจากกัน จึงไม่มี hitbox ซ้อนทับ ส่วน desktop ยังคลิกจุดบนภาพได้ แผงใช้ native dialog มี focus loop, Escape และคืนโฟกัสให้ปุ่มที่เปิด

## ขอบเขตความถูกต้องของข้อมูล

การเป็น `isDemo: false` บอกว่าเป็นบันทึกภาคสนาม ไม่ได้แปลว่าชื่อเรียก วัสดุ จำนวน หรือลำดับงานได้รับการยืนยันแล้ว โดยเฉพาะคำอธิบายเกล็ดพญานาค จำนวนเกล็ด และลำดับงาน 7 ขั้น ยังต้องเทียบแหล่งบันทึกหรือให้ช่างยืนยัน ข้อมูลในฐานข้อมูลไม่ได้ถูกแต่งใหม่เพื่อเติมช่องว่างในรอบนี้
